=== 6. QOS ПРОВЕРКА (/TF_STATIC) ===
# ВАЖНО: Убедиться, что работает только один robot_state_publisher.
# ros2 node list должен показать /robot_state_publisher один раз.

# Терминал 2: Генерация qos-before.txt (дефект не нужен, это проверка профиля)
# Здесь мы фиксируем профиль издателя и поведение позднего подписчика

{
  echo '## topic info /tf_static'
  ros2 topic info /tf_static --verbose

  echo ''
  echo '## echo transient_local (ожидаем данные)'
  timeout 4 ros2 topic echo /tf_static --once \
    --qos-durability transient_local --qos-reliability reliable
  echo "exit=$?"

  echo ''
  echo '## echo volatile (ожидаем таймаут)'
  timeout 4 ros2 topic echo /tf_static --once \
    --qos-durability volatile --qos-reliability reliable
  echo "exit=$?"
} > evidence/pr06/tf-qos.txt 2>&1

# Дописать текстовое объяснение
cat >> evidence/pr06/tf-qos.txt <<'EOF'

## Вывод

/tf_static публикуется RELIABLE и TRANSIENT_LOCAL, поэтому поздний
подписчик с тем же профилем получает сохранённое последнее сообщение.
Подписчик с VOLATILE не получает исторические статические преобразования.

/tf используется для меняющихся преобразований и обычно публикуется
RELIABLE + VOLATILE: старые трансформации не нужны, важны актуальные.
